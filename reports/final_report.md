### นายศุภชัย คนเพียร — Coder (ระบบปรับความยากและ DevOps)

- พัฒนา `src/difficulty.py` วิเคราะห์ **อัตราการกดทันย้อนหลัง** ของผู้เล่น
  แล้วปรับเวลาและจำนวนตัวอักษรของมินิเกม QTE ให้เหมาะกับฝีมือ
- ใส่ทั้ง **พื้นและเพดาน** ป้องกันไม่ให้บีบจนเล่นไม่ได้ — เวลาไม่ต่ำกว่า 4.0 และไม่เกิน 12.0 วินาที
  ทดสอบวนคันเบ็ดเลเวล 1-29 ทุกกรณี ค่าไม่เคยหลุดกรอบ
- **ต่อระบบเข้ากับหน้าตกปลาจริง** ผ่านเมธอด `apply_to()` ที่ปรับมินิเกมจากภายนอก
  จึงไม่ต้องแก้ `src/minigame.py` ซึ่งเป็นของ Sprint 2
- เพิ่มขั้นตอน **วัด test coverage** เข้าไปใน CI Pipeline และอัปโหลด `coverage.xml` เป็น artifact
- **Badge สถานะ CI** ที่หัว `README.md` ให้เห็นผลรันล่าสุดทันที
- เพิ่ม `LICENSE` และ `CONTRIBUTING.md` ให้ครบตามมาตรฐาน repository
- **ทำส่วน CD (Continuous Delivery)** — `release.yml` ทำงานเมื่อ push tag `vX.Y.Z`
  เรียก `ci.yml` ชุดเดิมผ่าน `workflow_call` ให้ lint + test ก่อน แล้วตรวจว่า tag · `__version__` ·
  CHANGELOG ตรงกันด้วย `tools/release.py` จากนั้นแพ็กเกมด้วย `git archive` และสร้าง GitHub Release
  โดยใช้หัวข้อของเวอร์ชันนั้นใน CHANGELOG เป็นคำอธิบาย
- เพิ่ม `src/update_checker.py` ให้เกมถาม GitHub Releases ในเบื้องหลังตอนเปิดเกม
  ถ้ามีเวอร์ชันใหม่กว่าจะแจ้งบนหน้าแรกพร้อมปุ่มไปหน้าดาวน์โหลด **แจ้งอย่างเดียว ไม่เขียนทับเกมเอง**
  ใช้หลักเดียวกับ Open Fisheries — ไม่มีเน็ตหรือยังไม่มี release เกมก็เล่นได้ตามปกติ
- เขียน `tests/test_update_checker.py` **36 เคส** (ใช้ GitHub ปลอม ไม่ยิงเน็ตจริง) และ
  `tests/test_release_tool.py` **16 เคส** ซึ่งมีเคสที่ตรวจ CHANGELOG จริงของโปรเจกต์
  ถ้าแก้ `__version__` แล้วลืมเขียน CHANGELOG เทสต์จะแดงทันที

### นายธนภัทร สมบูรณ์ — Coder (ประวัติการจับปลาและสถิติย้อนหลัง)

- งานเดิมที่วางแผนไว้คือ `src/ai_quest.py` ซึ่ง**ทำเสร็จแล้วใน Sprint 3** ในชื่อ `src/ai_fishing.py`
  จึงเปลี่ยนมารับงานที่ README สัญญาไว้แต่ยังไม่มีใครทำ — **"สะสมประวัติการจับปลาลงไฟล์ JSON
  แล้วนำมาสรุปย้อนหลัง"** (README หัวข้อ 4 และ Stretch Features)
- พัฒนา `src/catch_log.py` คลาส `CatchLog` จดปลาทุกตัวที่จับได้ลง `data/catch_log.jsonl`
  บรรทัดละหนึ่งตัว **เขียนต่อท้ายอย่างเดียว** ขายปลาไปแล้วประวัติก็ยังอยู่
  ต่างจาก `GameState.summary()` ที่สรุปได้แค่ปลาที่ยังอยู่ในกระเป๋า
- ใช้ประสบการณ์ชั้นข้อมูลจาก Sprint 2 — ไฟล์หาย หรือบรรทัดสุดท้ายขาดครึ่งเพราะปิดโปรแกรมระหว่างเขียน
  ต้องไม่ทำให้เกม crash ข้ามเฉพาะบรรทัดที่เสียแล้วนับจำนวนไว้แจ้งผู้เล่น
- แยก `summarize()` เป็นตรรกะล้วนที่ไม่แตะไฟล์ ทดสอบสถิติได้ตรงๆ และฉีดนาฬิกาเข้ามาได้
  เวลาที่บันทึกในเทสต์จึงแน่นอน
- ต่อเข้ากับเกม — `FishingPresenter` จดทุกครั้งที่จับได้ และหน้าแรกมีการ์ด **สถิติตลอดการเล่น**
- เขียน `tests/test_catch_log.py` **27 เคส** ใช้ `tmp_path` ทุกเคส ไม่แตะไฟล์ประวัติจริง

### นายภาวัต วงศ์มาลาสิทธิ์ — Debugger / QA

- เขียน `tests/test_difficulty.py` ตรวจว่าระบบปรับความยาก
  **ไม่ทำให้เวลาต่ำกว่าขั้นต่ำ** ไม่ว่าสถิติการเล่นจะแย่แค่ไหน
- เพิ่มเทสต์ว่าประวัติความยาก**ไม่ทำให้ไฟล์เซฟโตไม่สิ้นสุด** (เก็บสูงสุด 20 รอบ)
  และไฟล์เซฟที่ `difficulty_data` เสียต้องไม่ทำให้เกม crash
- เพิ่ม `TestFishingDifficulty` 6 เคสใน `test_gui_logic.py` — ต่อกับรอบการตกปลา และเล่นได้แม้ไม่มีตัวปรับความยาก
- ตรวจ **UML Class Diagram** ว่าตรงกับโค้ดจริงหลังผสานกับงานของ Sprint 3
- ตรวจว่าตัวเลขทุกตัวในรายงานตรงกับผลรันจริง
- เทสต์ที่ดูแลในสปรินต์นี้ **42 เคส** — รวมกับของธนภัทร 27 เคสและของศุภชัย 52 เคส
  สปรินต์นี้เพิ่มทั้งหมด **121 เคส** ทั้งโปรเจกต์เป็น **437 เคส** ผ่านทั้งหมด

(`src/ai_fishing.py`) แล้ว push ขึ้น `main` ใน Sprint 3 พอจะนำงาน Final เข้ามา
จึงมีสองระบบที่ทำเรื่องเดียวกัน

| | งาน Final ที่พักไว้ | งานของ Sprint 3 ใน `main` |
|---|---|---|
| เรียก AI จริง | ยังไม่มีตัวเรียกโมเดล ใช้เควสต์สำรองเสมอ | เรียก Gemini ได้จริงเมื่อมี key |
| จำนวนเควสต์ต่อวัน | 1 ภารกิจ | 1–5 เควสต์ ไม่ซ้ำประเภท |
| หน้าจอ | การ์ดบนหน้าแรก | หน้าเควสต์แยก |
| ที่เก็บข้อมูล | `data/session.json` แยกจากไฟล์เซฟ | `quest_data` ในไฟล์เซฟหลัก |

**การแก้ไข:** ใช้ระบบของ Sprint 3 ต่อเพราะครบกว่า ตัด `ai_quest.py` ·
`session_store.py` · การ์ดภารกิจบนหน้าแรก และเทสต์ของสามส่วนนั้นออก
เก็บไว้เฉพาะส่วนที่ไม่ซ้ำ คือระบบปรับความยาก coverage ใน CI และเอกสาร

### 7.2 เก็บประวัติความยากไว้ที่ไหน — และทำไมประวัติการจับปลาถึงแยกไฟล์

**ปัญหา:** งาน Final เดิมเก็บประวัติความยากใน `data/session.json` แยกจากไฟล์เซฟ
ระหว่างพัฒนาเคยเจอบั๊กว่าเงินรางวัลถูกบันทึกในไฟล์หนึ่ง ส่วนเครื่องหมาย "รับรางวัลแล้ว"
อยู่อีกไฟล์ ถ้าปิดโปรแกรมผิดปกติระหว่างสองจังหวะ ผู้เล่นจะกดรับรางวัลซ้ำได้
ต้องแก้ด้วยการบังคับให้เขียนสองไฟล์พร้อมกันทุกครั้ง

**การแก้ไข:** Sprint 3 เลือกเก็บเควสต์ไว้ใน `GameState.quest_data` ซึ่งอยู่ในไฟล์เซฟหลักอยู่แล้ว
จึงเก็บประวัติความยากแบบเดียวกันใน `GameState.difficulty_data`

- `autosave()` ครั้งเดียวเขียนเงิน กระเป๋าปลา เควสต์ และความยากลงไฟล์เดียว ไม่มีจังหวะที่สองไฟล์ไม่ตรงกัน
- ไม่ต้องมี `SessionStore` และไม่ต้องมีไฟล์ที่สองให้ดูแล
- ไฟล์เซฟรุ่นเก่าที่ไม่มีฟิลด์นี้ยังโหลดได้ ค่าที่เสีย (ไม่ใช่ dict) ถือเป็นค่าว่าง

ผลข้างเคียงคือไฟล์เซฟจะโตขึ้นทุกรอบที่เล่น จึงให้ `DifficultyTuner` เก็บไว้แค่ **20 รอบล่าสุด**
ซึ่งพอสำหรับการตัดสินระดับที่ใช้แค่ 5 รอบล่าสุดอยู่แล้ว

**ส่วนประวัติการจับปลากลับแยกไฟล์** (`data/catch_log.jsonl`) เพราะเป็นคนละลักษณะ —
แต่ละบรรทัดเป็นเหตุการณ์ที่จบในตัวเอง ไม่มีค่าใดในไฟล์เซฟคำนวณมาจากมัน และมันโตขึ้นตลอดการเล่น
ถ้าใส่ไว้ใน `save_game.json` ทุก `autosave()` จะต้องเขียนประวัติทั้งหมดซ้ำ
แยกเป็นไฟล์ต่อท้ายจึงเขียนแค่บรรทัดใหม่บรรทัดเดียวต่อปลาหนึ่งตัว

**บทเรียน:** ข้อมูลที่ต้องสอดคล้องกันควรอยู่ในที่เดียว ส่วนข้อมูลที่เป็นบันทึกเหตุการณ์และโตไม่หยุด
ควรแยกเป็นไฟล์ต่อท้าย เลือกที่เก็บตามลักษณะของข้อมูล ไม่ใช่ใช้กฎเดียวกับทุกอย่าง
