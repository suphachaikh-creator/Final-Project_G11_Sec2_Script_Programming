## 1. Project Title

**HOW DO YOU FISH** — เกมจำลองการตกปลาแบบ Desktop GUI

---

## 2. Problem Statement

ฐานข้อมูลประมงระดับโลกมีข้อมูลปลานับหมื่นชนิด แต่ถูกเก็บในรูปตารางและรหัสวิชาการที่คนทั่วไป
ไม่มีเหตุผลจะเปิดอ่าน คนส่วนใหญ่จึงรู้จักปลาเพียงไม่กี่ชนิดที่พบบนโต๊ะอาหาร

สื่อการเรียนรู้เรื่องทรัพยากรประมงที่มีอยู่มักเป็นเอกสารและสถิติ ไม่มีแรงจูงใจให้กลับมาเปิดซ้ำ
ความรู้จึงไม่ติดตัวผู้อ่าน ต่อให้ทำเป็นโปรแกรมก็มักเป็นเพียงหน้าต่างค้นหาที่พิมพ์คำแล้วได้ตารางกลับมา
จบในครั้งเดียว ไม่มีอะไรทำให้ผู้ใช้อยากกลับมาเปิดอีก

**สรุปปัญหา:** ข้อมูลปลาจริงมีอยู่และเข้าถึงได้ฟรี แต่ไม่มีรูปแบบการนำเสนอที่ทำให้คนอยากเปิดดูซ้ำ

---

## 3. Proposed Solution

HOW DO YOU FISH คือเกมตกปลาแบบ Desktop Application ที่มีหน้าต่างกราฟิก (GUI) โดยดึงข้อมูล
ชนิดปลาจริงมาเป็นตัวปลาในเกม ผู้เล่นเลือกสถานที่ตกปลา กดหย่อนเบ็ด เล่นมินิเกมสู้แรงปลา
แล้วนำปลาที่จับได้ไปขายเพื่ออัปเกรดเหยื่อและคันเบ็ดให้จับปลาที่ใหญ่และมีมูลค่าสูงขึ้น

ทุกครั้งที่จับปลาได้ ผู้เล่นจะเห็นชื่อสามัญ ชื่อวิทยาศาสตร์ และกลุ่มของปลาชนิดนั้น
ความรู้เรื่องสายพันธุ์จึงถูกส่งผ่านไปโดยที่ผู้เล่นไม่รู้ตัวว่ากำลังอ่านฐานข้อมูลประมง

**วงจรการเล่น:** เลือกสถานที่ → ตกปลา (มินิเกม QTE) → ขายและอัปเกรด → กลับไปตกปลาที่ยากขึ้น

## 5. API(s) to Use

โครงการนี้ใช้ **Public API สองตัวที่เติมเต็มกัน** ทั้งคู่เปิดให้เรียกฟรีและไม่ต้องใช้ API Key

| API | ให้ข้อมูลอะไร | ทำไมต้องใช้ |
|---|---|---|
| **WoRMS** | แหล่งที่อยู่ (น้ำจืด · น้ำเค็ม · น้ำกร่อย) และอนุกรมวิธาน | เป็น API เดียวที่บอกแหล่งน้ำได้ ใช้แยกสถานที่ตกปลา |
| **Open Fisheries** | ชื่อสามัญภาษาอังกฤษ | ให้ผู้เล่นเห็น `Atlantic salmon` แทน `Salmo salar` |

### API ที่ 1 — WoRMS (World Register of Marine Species)

| หัวข้อ | รายละเอียด |
|---|---|
| **API Name** | WoRMS — World Register of Marine Species |
| **Documentation Link** | https://www.marinespecies.org/rest/ |
| **Endpoint** | `GET /AphiaRecordsByVernacular/{ชื่อสามัญ}?like=true` |
| **Type of Data** | ข้อมูลอนุกรมวิธานและแหล่งที่อยู่ของสิ่งมีชีวิตทางน้ำ (JSON) |
| **ไฟล์ในโปรเจกต์** | `src/worms_api.py` |

**ทำไมต้องใช้ endpoint ที่ค้นจากชื่อสามัญ**

WoRMS มีสอง endpoint ที่ใช้ค้นได้ — `AphiaRecordsByName` ค้นจาก**ชื่อวิทยาศาสตร์**
ส่วน `AphiaRecordsByVernacular` ค้นจาก**ชื่อสามัญ** ทีมทดสอบทั้งสองตัวแล้วพบว่า
การค้นคำอย่าง `fish` หรือ `shark` ด้วยตัวแรกจะไปตรงกับสกุลของสัตว์กลุ่มอื่นที่สะกดคล้ายกัน
เช่น *Fisherana* ซึ่งเป็นหนอนทะเล **ผลคือได้ปลากลับมา 0 จาก 115 รายการ**
ส่วนตัวหลังค้นเจอปลาจริง **650 ชนิด** จึงเลือกใช้ตัวหลังเป็นหลัก

**การกรองข้อมูล 3 ชั้น**

| ชั้นที่กรอง | เงื่อนไข | เหตุผล |
|---|---|---|
| 1. เป็นปลาจริง | `class` ต้องอยู่ใน 14 ชั้นทางอนุกรมวิธานของปลา | WoRMS มีทั้งหอย ปู หนอน ไม่ใช่ปลาอย่างเดียว |
| 2. ชื่อที่ยอมรับ | `status` ต้องเป็น `accepted` | ตัดชื่อพ้องและชื่อที่เลิกใช้แล้วออก |
| 3. ตรงแหล่งน้ำ | `isFreshwater` · `isMarine` · `isBrackish` ต้องเป็นจริง | แยกปลาให้ตรงกับสถานที่ตกปลาที่ผู้เล่นเลือก |

### API ที่ 2 — Open Fisheries

| หัวข้อ | รายละเอียด |
|---|---|
| **API Name** | Open Fisheries |
| **Documentation Link** | https://www.openfisheries.org/api/ |
| **Endpoint** | `GET https://www.openfisheries.org/api/landings/species.json` |
| **Type of Data** | รายชื่อสัตว์น้ำพร้อมชื่อสามัญภาษาอังกฤษ (JSON Array) |
| **ไฟล์ในโปรเจกต์** | `src/openfisheries_api.py` |

**ผลการทดสอบจริง** — เรียกสำเร็จได้ **11,562 รายการ** สร้างเป็นตารางจับคู่
ชื่อวิทยาศาสตร์ → ชื่อสามัญ ได้ **8,672 คู่**

### การรวมข้อมูลสอง API เข้าด้วยกัน

`src/fish_api.py` ทำหน้าที่ประสาน โดยจับคู่ทั้งสองแหล่งด้วย **ชื่อวิทยาศาสตร์**

```
WoRMS  ──► ชนิดปลา + แหล่งน้ำ + วงศ์
                    │
                    ├── จับคู่ด้วย scientific_name
                    │
Open Fisheries ──► ชื่อสามัญภาษาอังกฤษ
                    │
                    ▼
          ชื่อที่แสดงในเกม = ชื่อสามัญ (ถ้ามี) หรือชื่อวิทยาศาสตร์
```

**ผลที่ดึงได้จริงจากทั้งสอง API**

| สถานที่ในเกม | ฟิลด์ของ WoRMS | จำนวนชนิด | มีชื่อสามัญ |
|---|---|---|---|
| ทะเลสาบน้ำจืด | `isFreshwater` | 111 | 51 |
| ทะเลลึก | `isMarine` | 316 | 217 |
| ปากแม่น้ำน้ำกร่อย | `isBrackish` | 126 | 88 |

**ตัวอย่างการเรียกใช้**

```python
# WoRMS — หาชนิดปลาพร้อมแหล่งที่อยู่
response = requests.get(
    f"{BASE_URL}/AphiaRecordsByVernacular/{word}",
    params={"like": "true"},
    headers={"Accept": "application/json", "User-Agent": USER_AGENT},
    timeout=20,
)
if response.status_code in (204, 404):   # WoRMS ตอบ 204 เมื่อค้นไม่เจอ
    return []
response.raise_for_status()
records = response.json()
```

### การจัดการข้อผิดพลาด

| สถานการณ์ | ผลที่เกิดขึ้น |
|---|---|
| WoRMS ค้นไม่เจอ (`204` / `404`) | ถือเป็นผลลัพธ์ว่าง ไม่ใช่ข้อผิดพลาด แล้วค้นคำถัดไปต่อ |
| WoRMS เชื่อมต่อไม่ได้ · ตอบช้า · `5xx` · ไม่ใช่ JSON | สลับไปใช้ข้อมูลสำรองในเครื่องทั้งหมด |
| **Open Fisheries ล้มเหลว** | เกม**ยังเล่นได้ตามปกติ** เพียงแต่แสดงชื่อวิทยาศาสตร์แทนชื่อสามัญ |

จุดสำคัญคือทั้งสอง API มีระดับความสำคัญต่างกัน — WoRMS เป็นข้อมูลหลักที่ขาดไม่ได้
ส่วน Open Fisheries เป็นข้อมูลเสริม ล้มเหลวได้โดยไม่กระทบการเล่น

### ระบบสำรองและแคช

ดึงจาก WoRMS **ครั้งเดียว** แล้วแยกแหล่งน้ำเอง ไม่ยิงซ้ำสามรอบ และแคชผลไว้ต่อหนึ่งแหล่งน้ำ
ถ้าเชื่อมต่อไม่ได้เลย เกมจะอ่านจาก `data/fish_species.json` ที่เตรียมไว้ล่วงหน้า
(แหล่งน้ำละ 30 ชนิด **มีชื่อสามัญครบ 100%**) **เกมจึงเล่นได้แม้ไม่มีอินเทอร์เน็ต**

สร้างหรือรีเฟรชไฟล์สำรองได้ด้วย

```bash
python tools/seed_fish_data.py --dry-run     # ดูผลลัพธ์โดยไม่เขียนไฟล์
python tools/seed_fish_data.py --limit 30    # เก็บแหล่งน้ำละ 30 ชนิด
```

## 6. Data Persistence Plan

**File-based (JSON)**

**รายละเอียด:** บันทึกสถานะของผู้เล่นลงไฟล์ `save_game.json` โดยเซฟอัตโนมัติทุกครั้งที่จับปลาได้
หรือทำรายการในร้านค้า ผู้เล่นไม่ต้องกดเซฟเอง

**เหตุผลที่เลือก JSON แทนฐานข้อมูล**

1. ข้อมูลเป็นสถานะของผู้เล่นคนเดียว ไม่มีความสัมพันธ์ระหว่างตารางให้ต้องจัดการ
2. กระเป๋าปลาเป็น `list` ของ `dict` อยู่แล้ว แปลงเป็น JSON ได้ตรงไปตรงมา
3. `json` เป็นไลบรารีมาตรฐานของ Python ไม่ต้องติดตั้งเพิ่ม
4. ไฟล์อ่านออกด้วยตาเปล่า ทำให้ตรวจสอบและแก้ไขระหว่างพัฒนาได้ง่าย
5. ป้องกันด้วย `os.path.exists` ก่อนเปิด และครอบ `try-except` ตอนอ่าน ไฟล์เสียหายก็เริ่มเกมใหม่ได้โดยไม่ crash

**โครงสร้างไฟล์**

```json
{
    "money": 1250,
    "bait_level": 3,
    "rod_level": 2,
    "inventory": [
        {
            "name": "Nile tilapia",
            "location": "freshwater",
            "weight_kg": 2.4,
            "price": 180
        }
    ]
}
```

## 7. Framework Style

**OOP (classes, objects, encapsulation)**

### เทคโนโลยีของส่วนติดต่อผู้ใช้

ส่วนติดต่อผู้ใช้เป็น **Desktop GUI พัฒนาด้วย Tkinter + ttk** ซึ่งเป็นไลบรารีมาตรฐานของ Python
คู่มือของรายวิชาระบุไว้ว่า Presentation Layer เป็นได้ทั้ง CLI หรือ GUI โครงการนี้เลือก GUI

| เหตุผลที่เลือก Tkinter | รายละเอียด |
|---|---|
| ไม่ต้องติดตั้งเพิ่ม | ติดมากับ Python บน Windows อยู่แล้ว `requirements.txt` จึงไม่บวมและ CI ติดตั้งเร็ว |
| มีตัวจับเวลาในตัว | `root.after()` ใช้ทำนับถอยหลังของมินิเกม QTE ได้ทันที ไม่ต้องพึ่ง `msvcrt` หรือ `select` ที่เขียนคนละแบบในแต่ละระบบปฏิบัติการ |
| รับปุ่มกดได้โดยตรง | `bind("<Key>")` อ่านการกดปุ่มแบบเรียลไทม์ ทำให้มินิเกมทำงานได้ตรงตามที่ออกแบบ |
| มีตารางข้อมูลสำเร็จรูป | `ttk.Treeview` รองรับหลายคอลัมน์และคลิกหัวคอลัมน์เพื่อเรียงลำดับ เหมาะกับหน้าคลังสินค้า |

**หลักการที่ยึด (Separation of Concerns)**

- ชั้นแสดงผลไม่คำนวณตรรกะ ทำหน้าที่แค่รับคลิก วาดผลลัพธ์ และเรียกเมธอดของ `GameState`
- **ชั้นตรรกะไม่ import `tkinter` เลย** จึงเขียน unit test ได้โดยไม่ต้องเปิดหน้าต่าง
- ชั้นข้อมูลไม่รู้จัก API
- **ตัวจับเวลาของมินิเกมแยกออกมาเป็นพารามิเตอร์ที่แทนที่ได้** ตอนเล่นจริงใช้ `root.after()`
  ของ Tkinter ส่วนตอนทดสอบใส่ตัวจับเวลาจำลองเข้าไป ทำให้ทดสอบได้โดยไม่ต้องรอเวลาจริง

  ซึ่งทำได้เพราะ `GameState` และ `QTEMinigame` ไม่ผูกกับ Tkinter อยู่แล้ว
- **งานฝั่งหน้าจอมากกว่าแบบ CLI** — จึงกำหนดให้ Sprint 1 โฟกัสที่การวางหน้าจอทั้งสี่หน้า

## 9. Features

1. **เลือกสถานที่ตกปลา** — เลือกระหว่างทะเลสาบน้ำจืด ทะเลลึก และปากแม่น้ำน้ำกร่อย จากหน้าจอ Fishing ระบบกรองชนิดปลาจากฟิลด์ `isFreshwater` · `isMarine` · `isBrackish` ของ WoRMS ให้ตรงกับแหล่งน้ำ
2. **มินิเกม QTE สู้แรงปลา** — สุ่มตัวอักษรให้กดแข่งกับแถบเวลาที่ลดลงแบบเรียลไทม์ คันเบ็ดเลเวลสูงขึ้นจะได้เวลามากขึ้น กดถูกได้เวลาเพิ่ม
3. **คำนวณน้ำหนักและราคาปลา** — สุ่มน้ำหนักตามชนิดปลา แล้วคิดราคาจากน้ำหนักคูณกับเลเวลเหยื่อ พร้อมแสดงชื่อวิทยาศาสตร์ของปลาที่จับได้
4. **ร้านค้าอัปเกรดอุปกรณ์** — นำเงินที่ได้ไปเพิ่มเลเวลเหยื่อ (จับปลาใหญ่ขึ้น) หรือคันเบ็ด (เพิ่มเวลาสู้ปลา) ปุ่มซื้อจะถูกปิดเองเมื่อเงินไม่พอ
5. **คลังสินค้า ค้นหา กรอง เรียงลำดับ** — ตาราง `ttk.Treeview` พร้อมช่องค้นหาชื่อปลา ตัวกรองแหล่งน้ำ และคลิกหัวคอลัมน์เพื่อเรียงตามน้ำหนักหรือราคา
6. **บันทึกและเล่นต่ออัตโนมัติ** — เก็บเงิน กระเป๋าปลา และเลเวลอุปกรณ์ลงไฟล์ JSON ทุกครั้งที่สถานะเปลี่ยน และโหลดคืนเมื่อเปิดโปรแกรมใหม่

## 10. Stretch Features (Optional)

- **เควสต์ประจำวันด้วย AI** — ส่งรายการปลาที่ผู้เล่นมีให้โมเดลภาษา แล้วให้สร้างภารกิจประจำวัน
  เช่น *"จับปลาทะเลน้ำหนักเกิน 5 กิโลกรัมให้ได้ 3 ตัว"* ทำให้เกมมีเป้าหมายใหม่ทุกวัน
  และตอบโจทย์หัวข้อ AI Integration ของรายวิชา

## การติดตั้งและใช้งาน (Setup & Usage)

### ติดตั้ง

```bash
pip install -r requirements.txt
```

### เล่นเกม

```bash
python main.py
```

เกมจะดึงชนิดปลาจาก WoRMS API ให้อัตโนมัติเมื่อเปิดเกม ถ้าเชื่อมต่อไม่ได้
จะสลับไปใช้ฐานข้อมูลสำรองในเครื่อง (`data/fish_species.json`) แล้วแจ้งให้ผู้เล่นทราบ
จึงเล่นได้แม้ไม่มีอินเทอร์เน็ต

### รันชุดทดสอบและตรวจมาตรฐานโค้ด

```bash
python -m pytest -q
flake8 .
```

ชุดทดสอบทั้งหมดทำงานแบบออฟไลน์ ไม่ยิงเครือข่ายจริงและไม่แตะไฟล์เซฟจริง
