## 1. Project Title

**HOW DO YOU FISH** — เกมจำลองการตกปลาแบบ Desktop GUI

---

## 2. Problem Statement

ฐานข้อมูลประมงระดับโลกมีข้อมูลปลานับหมื่นชนิด แต่ถูกเก็บในรูปตารางและรหัสวิชาการที่คนทั่วไป
ไม่มีเหตุผลจะเปิดอ่าน คนส่วนใหญ่จึงรู้จักปลาเพียงไม่กี่ชนิดที่พบบนโต๊ะอาหาร

สื่อการเรียนรู้เรื่องทรัพยากรประมงที่มีอยู่มักเป็นเอกสารและสถิติ ไม่มีแรงจูงใจให้กลับมาเปิดซ้ำ
ความรู้จึงไม่ติดตัวผู้อ่าน ต่อให้ทำเป็นโปรแกรมก็มักเป็นเพียงหน้าต่างค้นหาที่พิมพ์คำแล้วได้ตารางกลับมา
จบในครั้งเดียว ไม่มีอะไรทำให้ผู้ใช้อยากกลับมาเปิดอีก

**สรุปปัญหา:** ข้อมูลปลาจริงมีอยู่และเข้าถึงได้ฟรี แต่ไม่มีรูปแบบการนำเสนอที่ทำให้คนอยากเปิดดูซ้ำ

---

## 3. Proposed Solution

HOW DO YOU FISH คือเกมตกปลาแบบ Desktop Application ที่มีหน้าต่างกราฟิก (GUI) โดยดึงข้อมูล
ชนิดปลาจริงมาเป็นตัวปลาในเกม ผู้เล่นเลือกสถานที่ตกปลา กดหย่อนเบ็ด เล่นมินิเกมสู้แรงปลา
แล้วนำปลาที่จับได้ไปขายเพื่ออัปเกรดเหยื่อและคันเบ็ดให้จับปลาที่ใหญ่และมีมูลค่าสูงขึ้น

ทุกครั้งที่จับปลาได้ ผู้เล่นจะเห็นชื่อสามัญ ชื่อวิทยาศาสตร์ และกลุ่มของปลาชนิดนั้น
ความรู้เรื่องสายพันธุ์จึงถูกส่งผ่านไปโดยที่ผู้เล่นไม่รู้ตัวว่ากำลังอ่านฐานข้อมูลประมง

**วงจรการเล่น:** เลือกสถานที่ → ตกปลา (มินิเกม QTE) → ขายและอัปเกรด → กลับไปตกปลาที่ยากขึ้น

## 4. Domain

**Daily App , Data Analysis & Management**

•ดึงข้อมูลชนิดปลาจริงจาก Public API แล้วนำมาจัดเก็บเป็นโครงสร้างของตัวเอง
•มีระบบค้นหา กรองตามกลุ่มปลา และเรียงลำดับตามน้ำหนักหรือราคา
•สรุปสถิติการจับปลาของผู้เล่นจากประวัติที่บันทึกไว้

## 5. API(s) to Use

ข้อกำหนดของรายวิชาระบุว่าใช้ได้ทั้ง *public API* และ *self-made mock API*
โครงการนี้เลือก **พัฒนา API ขึ้นเอง** เป็นตัวหลัก โดยใช้ข้อมูลตั้งต้นจาก public API จริง
จึงได้ทั้งข้อมูลที่เชื่อถือได้ และความสามารถในการควบคุมระบบตอนสาธิต

### API หลัก — Fish Mock API

| หัวข้อ | รายละเอียด |
|---|---|
| **API Name** | Fish Mock API |
| **เขียนด้วย** | `http.server` ของ Python — ไม่ต้องติดตั้งไลบรารีเพิ่ม |
| **Base URL** | `http://127.0.0.1:8000` |
| **Type of Data** | ชนิดปลาแยกตามแหล่งน้ำ และสถิติการจับปลาของผู้เล่น (JSON) |
| **API Key** | ไม่ต้องใช้ |
| **ไฟล์** | `api_server.py` (ฝั่งเซิร์ฟเวอร์) · `src/fish_api.py` (ฝั่งเกมที่เรียกใช้) |

**Endpoint ที่ออกแบบไว้**

| Method | Endpoint | หน้าที่ | ผลลัพธ์ |
|---|---|---|---|
| `GET` | `/fish?location=freshwater` | ดึงชนิดปลาของทะเลสาบน้ำจืด | `200` + JSON Array |
| `GET` | `/fish?location=deepsea` | ดึงชนิดปลาของทะเลลึก | `200` + JSON Array |
| `POST` | `/catches` | บันทึกปลาที่ผู้เล่นจับได้ | `201` + รายการที่บันทึก |
| `GET` | `/stats` | สรุปสถิติการจับปลาทั้งหมด | `200` + JSON Object |

**กรณีข้อผิดพลาดที่ต้องรับมือ**

| สถานการณ์ | ผลที่เกิดขึ้น |
|---|---|
| ไม่ระบุ `location` หรือระบุค่าที่ไม่รู้จัก | เซิร์ฟเวอร์ตอบ `400 Bad Request` |
| เรียก endpoint ที่ไม่มีอยู่ | เซิร์ฟเวอร์ตอบ `404 Not Found` |
| ส่ง body ที่ไม่ใช่ JSON ไปที่ `/catches` | เซิร์ฟเวอร์ตอบ `400 Bad Request` |
| ยังไม่ได้เปิดเซิร์ฟเวอร์ | ฝั่งเกมดัก `requests.exceptions.ConnectionError` แล้วแจ้งผู้เล่น |
| เซิร์ฟเวอร์ตอบช้าเกินกำหนด | ฝั่งเกมดัก `requests.exceptions.Timeout` |

### แหล่งข้อมูลตั้งต้น — Open Fisheries API

ข้อมูลปลาที่ Fish Mock API เสิร์ฟ **ไม่ได้แต่งขึ้นเอง** แต่ดึงจาก public API จริงหนึ่งครั้ง
ด้วยสคริปต์ `seed_fish_data.py` แล้วเก็บไว้เป็นไฟล์ `data/fish_species.json`

| หัวข้อ | รายละเอียด |
|---|---|
| **API Name** | Open Fisheries API |
| **Documentation Link** | https://www.openfisheries.org/api/ |
| **Endpoint** | `GET https://www.openfisheries.org/api/landings/species.json` |
| **Type of Data** | รายชื่อชนิดปลาและสัตว์น้ำ (JSON Array) |
| **ผลการทดสอบจริง** | เรียกสำเร็จ ได้ข้อมูล **11,562 ชนิด** โดย **8,686 ชนิด** มีชื่อภาษาอังกฤษพร้อมใช้งาน |

**ฟิลด์ที่นำมาใช้**

| ฟิลด์ | ความหมาย | ใช้ทำอะไรในเกม |
|---|---|---|
| `english_name` | ชื่อสามัญ | ชื่อปลาที่แสดงให้ผู้เล่นเห็น |
| `scientific_name` | ชื่อวิทยาศาสตร์ | แสดงเป็นเกร็ดความรู้ตอนจับได้ |
| `isscaap` | รหัสกลุ่มปลา | แยกปลาน้ำจืดกับปลาทะเลตามสถานที่ตกปลา |
| `a3_code` | รหัสสากล 3 ตัวอักษร | ใช้เป็นคีย์อ้างอิงชนิดปลา |

**การแยกแหล่งน้ำด้วยรหัส ISSCAAP:** กลุ่ม 11–25 คือปลาน้ำจืดและปลาสองน้ำ (ใช้กับ *ทะเลสาบน้ำจืด*)
ส่วนกลุ่ม 31–39 คือปลาทะเล (ใช้กับ *ทะเลลึก*) การกรองนี้ทำที่ฝั่ง Fish Mock API
ฝั่งเกมจึงขอเฉพาะปลาที่ต้องการได้เลย ไม่ต้องดึงข้อมูลทั้งหมดมากรองเอง

### เหตุผลที่เลือกพัฒนา API เอง

| เหตุผล | รายละเอียด |
|---|---|
| **ครอบคลุมทั้ง GET และ POST** | ข้อกำหนดระบุว่าต้องจัดการทั้ง GET และ POST แต่ public API ที่ใช้ได้ฟรีส่วนใหญ่เป็น read-only จึงสาธิต POST ไม่ได้ |
| **การสาธิตสดไม่ขึ้นกับอินเทอร์เน็ต** | Live Demo คิดเป็น 25 คะแนน จึงไม่ควรฝากความสำเร็จไว้กับเครือข่ายในห้องเรียน |
| **สาธิต Error Handling ได้จริง** | ปิดเซิร์ฟเวอร์ระหว่างสาธิตเพื่อแสดงว่าเกมดัก `ConnectionError` ได้โดยไม่ crash |
| **ออกแบบ endpoint ให้ตรงกับเกม** | กำหนดรูปแบบข้อมูลและการกรองได้เอง ไม่ต้องดัดข้อมูลจากรูปแบบที่ผู้อื่นกำหนด |

## 6. Data Persistence Plan

**File-based (JSON)**

**รายละเอียด:** บันทึกสถานะของผู้เล่นลงไฟล์ `save_game.json` โดยเซฟอัตโนมัติทุกครั้งที่จับปลาได้
หรือทำรายการในร้านค้า ผู้เล่นไม่ต้องกดเซฟเอง

**เหตุผลที่เลือก JSON แทนฐานข้อมูล**

1. ข้อมูลเป็นสถานะของผู้เล่นคนเดียว ไม่มีความสัมพันธ์ระหว่างตารางให้ต้องจัดการ
2. กระเป๋าปลาเป็น `list` ของ `dict` อยู่แล้ว แปลงเป็น JSON ได้ตรงไปตรงมา
3. `json` เป็นไลบรารีมาตรฐานของ Python ไม่ต้องติดตั้งเพิ่ม
4. ไฟล์อ่านออกด้วยตาเปล่า ทำให้ตรวจสอบและแก้ไขระหว่างพัฒนาได้ง่าย
5. ป้องกันด้วย `os.path.exists` ก่อนเปิด และครอบ `try-except` ตอนอ่าน ไฟล์เสียหายก็เริ่มเกมใหม่ได้โดยไม่ crash

**โครงสร้างไฟล์**

```json
{
    "money": 1250,
    "bait_level": 3,
    "rod_level": 2,
    "inventory": [
        {
            "name": "Nile tilapia",
            "location": "freshwater",
            "weight_kg": 2.4,
            "price": 180
        }
    ]
}
```

## 7. Framework Style

**OOP (classes, objects, encapsulation)**

### เทคโนโลยีของส่วนติดต่อผู้ใช้

ส่วนติดต่อผู้ใช้เป็น **Desktop GUI พัฒนาด้วย Tkinter + ttk** ซึ่งเป็นไลบรารีมาตรฐานของ Python
คู่มือของรายวิชาระบุไว้ว่า Presentation Layer เป็นได้ทั้ง CLI หรือ GUI โครงการนี้เลือก GUI

| เหตุผลที่เลือก Tkinter | รายละเอียด |
|---|---|
| ไม่ต้องติดตั้งเพิ่ม | ติดมากับ Python บน Windows อยู่แล้ว `requirements.txt` จึงไม่บวมและ CI ติดตั้งเร็ว |
| มีตัวจับเวลาในตัว | `root.after()` ใช้ทำนับถอยหลังของมินิเกม QTE ได้ทันที ไม่ต้องพึ่ง `msvcrt` หรือ `select` ที่เขียนคนละแบบในแต่ละระบบปฏิบัติการ |
| รับปุ่มกดได้โดยตรง | `bind("<Key>")` อ่านการกดปุ่มแบบเรียลไทม์ ทำให้มินิเกมทำงานได้ตรงตามที่ออกแบบ |
| มีตารางข้อมูลสำเร็จรูป | `ttk.Treeview` รองรับหลายคอลัมน์และคลิกหัวคอลัมน์เพื่อเรียงลำดับ เหมาะกับหน้าคลังสินค้า |

**หน้าจอที่ออกแบบไว้**

| หน้าจอ | เนื้อหา |
|---|---|
| Dashboard | แถบสถานะเงิน เลเวลเหยื่อ เลเวลคันเบ็ด จำนวนปลา และปุ่มเข้าสู่แต่ละหน้า |
| Fishing | เลือกสถานที่ ปุ่มหย่อนเบ็ด แถบรอปลากินเบ็ด และมินิเกม QTE พร้อมแถบเวลา |
| Shop | รายการอัปเกรดพร้อมราคา และปุ่มซื้อที่ปิดเองเมื่อเงินไม่พอ |
| Inventory | ตารางปลาที่จับได้ ช่องค้นหา ตัวกรองแหล่งน้ำ และเรียงลำดับด้วยการคลิกหัวคอลัมน์ |

**คลาสหลักและการแบ่งเลเยอร์**

| คลาส | เลเยอร์ | หน้าที่ |
|---|---|---|
| `Fish` | Domain | ข้อมูลปลาหนึ่งตัว — ชื่อ · แหล่งน้ำ · น้ำหนัก · ราคา และการคำนวณราคาจากน้ำหนัก |
| `FishAPI` | Integration | เรียก Fish Mock API ด้วย `requests` ทั้ง GET และ POST พร้อมดักข้อผิดพลาดของเครือข่าย |
| `FishHandler` | API Server | ฝั่งเซิร์ฟเวอร์ใน `api_server.py` เสิร์ฟชนิดปลาตามแหล่งน้ำ รับบันทึกการจับปลา และสรุปสถิติ |
| `SaveManager` | Data Access | บันทึกและโหลด `save_game.json` พร้อมดักไฟล์หายและไฟล์เสียหาย |
| `GameState` | Domain | สถานะการเล่นทั้งหมด — เงิน เลเวลอุปกรณ์ กระเป๋าปลา และกฎการซื้อขาย |
| `QTEMinigame` | Domain | ตรรกะมินิเกมล้วนๆ — สุ่มโจทย์ ตรวจคำตอบ คิดเวลาที่เหลือ โดยไม่รู้จัก Tkinter |
| `FishingApp` | Presentation | หน้าต่างหลัก (`tk.Tk`) ควบคุมการสลับหน้าจอและวาดแถบสถานะ |
| `DashboardFrame` · `FishingFrame` · `ShopFrame` · `InventoryFrame` | Presentation | แต่ละหน้าจอเป็นคลาสลูกของ `ttk.Frame` แยกไฟล์กันชัดเจน |

**หลักการที่ยึด (Separation of Concerns)**

- ชั้นแสดงผลไม่คำนวณตรรกะ ทำหน้าที่แค่รับคลิก วาดผลลัพธ์ และเรียกเมธอดของ `GameState`
- **ชั้นตรรกะไม่ import `tkinter` เลย** จึงเขียน unit test ได้โดยไม่ต้องเปิดหน้าต่าง
- ชั้นข้อมูลไม่รู้จัก API
- **ตัวจับเวลาของมินิเกมแยกออกมาเป็นพารามิเตอร์ที่แทนที่ได้** ตอนเล่นจริงใช้ `root.after()`
  ของ Tkinter ส่วนตอนทดสอบใส่ตัวจับเวลาจำลองเข้าไป ทำให้ทดสอบได้โดยไม่ต้องรอเวลาจริง

### ข้อควรระวังของการทำ GUI

- **เครื่องที่รัน CI ไม่มีหน้าจอ** — ถ้าชุดทดสอบสร้าง `tk.Tk()` ขึ้นมา ชุดทดสอบจะล้มบน
  GitHub Actions ทันที จึงกำหนดเป็นกฎว่า **เทสต์ยิงที่ชั้นตรรกะเท่านั้น ห้ามสร้างหน้าต่าง**
  ซึ่งทำได้เพราะ `GameState` และ `QTEMinigame` ไม่ผูกกับ Tkinter อยู่แล้ว
- **งานฝั่งหน้าจอมากกว่าแบบ CLI** — จึงกำหนดให้ Sprint 1 โฟกัสที่การวางหน้าจอทั้งสี่หน้า
  และการตรวจสอบอินพุตให้เสร็จก่อน แล้วค่อยต่อตรรกะจริงใน Sprint 2

## 9. Features

1. **เลือกสถานที่ตกปลา** — เลือกระหว่างทะเลสาบน้ำจืดกับทะเลลึกจากหน้าจอ Fishing ระบบกรองชนิดปลาจากรหัสกลุ่ม ISSCAAP ให้ตรงกับแหล่งน้ำ
2. **มินิเกม QTE สู้แรงปลา** — สุ่มตัวอักษรให้กดแข่งกับแถบเวลาที่ลดลงแบบเรียลไทม์ คันเบ็ดเลเวลสูงขึ้นจะได้เวลามากขึ้น กดถูกได้เวลาเพิ่ม
3. **คำนวณน้ำหนักและราคาปลา** — สุ่มน้ำหนักตามชนิดปลา แล้วคิดราคาจากน้ำหนักคูณกับเลเวลเหยื่อ พร้อมแสดงชื่อวิทยาศาสตร์ของปลาที่จับได้
4. **ร้านค้าอัปเกรดอุปกรณ์** — นำเงินที่ได้ไปเพิ่มเลเวลเหยื่อ (จับปลาใหญ่ขึ้น) หรือคันเบ็ด (เพิ่มเวลาสู้ปลา) ปุ่มซื้อจะถูกปิดเองเมื่อเงินไม่พอ
5. **คลังสินค้า ค้นหา กรอง เรียงลำดับ** — ตาราง `ttk.Treeview` พร้อมช่องค้นหาชื่อปลา ตัวกรองแหล่งน้ำ และคลิกหัวคอลัมน์เพื่อเรียงตามน้ำหนักหรือราคา
6. **บันทึกและเล่นต่ออัตโนมัติ** — เก็บเงิน กระเป๋าปลา และเลเวลอุปกรณ์ลงไฟล์ JSON ทุกครั้งที่สถานะเปลี่ยน และโหลดคืนเมื่อเปิดโปรแกรมใหม่

## 10. Stretch Features (Optional)

- **เควสต์ประจำวันด้วย AI** — ส่งรายการปลาที่ผู้เล่นมีให้โมเดลภาษา แล้วให้สร้างภารกิจประจำวัน
  เช่น *"จับปลาทะเลน้ำหนักเกิน 5 กิโลกรัมให้ได้ 3 ตัว"* ทำให้เกมมีเป้าหมายใหม่ทุกวัน
  และตอบโจทย์หัวข้อ AI Integration ของรายวิชา
- **ปรับความยากอัตโนมัติ (Dynamic Difficulty)** — วิเคราะห์อัตราการพิมพ์ทันของผู้เล่นย้อนหลัง
  แล้วปรับเวลาและจำนวนตัวอักษรของมินิเกม QTE ให้ยากขึ้นหรือง่ายลงเอง
- **สถิติการตกปลา** — เก็บประวัติการจับปลาแบบ append-only แล้วสรุปว่าปลาที่จับได้บ่อยที่สุดคือชนิดใด
  น้ำหนักเฉลี่ยเท่าไร และรายได้รวมแยกตามสถานที่เป็นเท่าใด
