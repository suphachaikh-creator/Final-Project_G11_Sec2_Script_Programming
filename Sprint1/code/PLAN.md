> งานที่เกินขอบเขตถูกย้ายไปพัฒนาต่อในโฟลเดอร์ [`../../Sprint2/code`](../../Sprint2/code)

## 1. ขอบเขตระบบ (System Scope)

- **แสดงหน้าจอข้อความต้อนรับ** — `ui.display_welcome_message()` แสดงแบนเนอร์และเมนูคำสั่งเบื้องต้นเมื่อเริ่มโปรแกรม
- **การรับคำสั่งจากผู้ใช้** — `app.get_command_input()` รับค่าอินพุต พร้อมใช้ `.strip()` ตัดช่องว่าง และ `.lower()` แปลงเป็นตัวพิมพ์เล็กใน `validators.normalize_command()`
- **การควบคุมลูปหลัก** — `app.run_app()` ใช้ `while True` ควบคุมการทำงาน พร้อมดักจับ `ValueError` เพื่อป้องกันโปรแกรมพัง
- **ข้อมูลจำลอง** — `mock_data.MOCK_BREEDS` ใช้แทนผลลัพธ์จาก API ที่จะเชื่อมจริงใน Sprint 2

## 3. โครงสร้างไฟล์

```
Sprint1/
├── code/                       # โฟลเดอร์นี้ — ซอร์สโค้ดทั้งหมด (working directory ของ CI)
│   ├── PLAN.md                 # เอกสารฉบับนี้
│   ├── README.md
│   ├── main.py                 # Entry point — python main.py
│   ├── requirements.txt        # pytest + flake8
│   ├── .flake8                 # ตั้งค่ามาตรฐาน PEP 8
│   ├── src/
│   │   ├── app.py              # ลูปหลัก + เมนู + ดักจับ ValueError
│   │   ├── ui.py               # ส่วนแสดงผลทั้งหมด (print เท่านั้น)
│   │   ├── validators.py       # ตรวจสอบอินพุต (ไม่มี input()/print() → เทสต์ง่าย)
│   │   └── mock_data.py        # ข้อมูลสายพันธุ์จำลองใน memory
│   └── tests/
│       ├── test_validators.py  # unit test ของฟังก์ชันตรวจสอบ
│       └── test_app_flow.py    # integration test จำลองการพิมพ์ของผู้ใช้
└── notebook/
    └── Sprint1_Report.ipynb    # รายงานประจำสปรินต์ (รันได้จริงทุกเซลล์)
```

**Pattern ที่ใช้:** UI/Core separation — `validators.py` ไม่รู้จัก `input()` และ `ui.py` ไม่คำนวณตรรกะ ทำให้ทดสอบแต่ละชั้นแยกกันได้
